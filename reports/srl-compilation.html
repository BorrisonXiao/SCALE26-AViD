SRL compilation and parse editing

One deterministic compilation path, with separate tests of an optional LLM editor. Full-corpus acceptance and meaning preservation are reported separately.

What the experiments support

The SRL-only compiler can be improved without selecting between independently generated logical forms. Linking the existing predicate frames by dependency relations addresses a major rejection cause. It still has meaning errors. On the 24 reviewed cases, the earlier SRL compiler has five faithful outputs; the new SRL graph has seven. Both LLM editor conditions also have seven. The editor experiments provide no observed gain in fully faithful outputs on this small check. Neither condition is selected automatically on individual claims.

Acceptance is not correctness. DeepProbLog consumes a well-formed logic program; it does not check whether that program preserves the original sentence. Improving acceptance requires separate meaning checks.

Meaning preservation

Within-corpus development. Full SRL conditions run on all 2,375 original claims. The two model conditions use the same 48 inputs: 24 known development-pilot cases and 24 additional IDs sampled uniformly before generation. The same assistant reviews the 24 random cases under all conditions. The SRL graph was frozen before that review; the restricted edit interface followed a separate 12-output regeneration pilot that changed correct roles. This is not human gold or a source-disjoint generalization study. Compilation counts do not establish semantic faithfulness.

Faithful means the stated meaning and principal bindings survive under the noted reading. Partial includes opaque internal relationships or missing detail. Incorrect means roles, asserted events, source/modal scope or identity changed. Refused is a compiler outcome, not a claim being false. The same assistant judged every condition; this is not independent human gold.

Examples to inspect: possible spacecraft routes and six floors including the bottom floor demonstrate recovered structure. people watching a robot perform exposes a wrong subject introduced by an editor. predicted rain and Mare Crisium’s location expose unresolved scope and noun-phrase detail.

What changed in the compiler

A complement is a clause used as an argument of another predicate. Its parent relation is retained without assuming the content occurred independently. A relative clause describes a noun and retains that noun as its owner. These contexts are passed to evidence functions; no new functions were trained for this experiment. Missing evidence functions still yield unknown. This extends the existing probabilistic framework, not its inference algorithm.

A smaller task for the LLM

The initial 12-output pilot regenerated complete SRL frames. It changed correct ARG1 labels to ARG0 and invented a predicate for the bare label “Sansha TV.” That pilot was stopped and is retained in the source archive. The replacement returns edit operations. Existing argument role labels cannot be renamed by this interface; an empty edit list preserves the original SRL record exactly. This also means that a wrong existing role label cannot be repaired.

The decoder restricts JSON structure, token positions and new predicate candidates. Valid references do not guarantee a correct span, new frame or clause interpretation. Every editor output still needs the same deterministic compilation checks and semantic review.

In the syntax/SRL condition, 72 of 90 proposed span edits repeat an unchanged span. The AMR condition has one invalid argument-index reference, caught after generation. The current grammar constrains source token bounds but does not express every dependency between a predicate ID and its argument-list length.

The previous free-logical-form system prompt has 491 whitespace-separated words; the edit prompt has 150. The model receives no logical-form version field. Protocol versions and hashes are recorded by Python outside the messages for reproducibility. Token indices are different: they identify the original words being edited.

Exact system prompt used for the edit experiments
Correct the supplied semantic role labeling (SRL) with minimal edits. Keep correct annotations unchanged. The original sentence is authoritative; dependency and optional AMR parses can be wrong.

Output JSON: {"edits":[{"predicate":TOKEN,"argument":ARGUMENT_INDEX,"span":[START,END]}],"remove_predicates":[TOKEN],"add_frames":[{"predicate":TOKEN,"arguments":[{"role":"ARG0","span":[START,END]}]}]}.

All token indices start at zero and span ends are inclusive. An edit identifies an existing predicate and its zero-based argument-list position. It changes only that argument's span; its existing PropBank role is preserved. Remove a frame only if it is spurious. Add a missing frame only from new_predicate_candidates, using predicate-specific PropBank ARG0–ARG5 or ARGM roles. Return empty lists when no correction is needed.

Keep every stated clause, participant, modifier, number, negation and modal. A clausal argument spans its content and has a separate predicate frame. Keep complete quoted content attached to its source. Bare names/labels need no predicate. Do not paraphrase or fact-check. Dependency rows are [token, POS, head, relation], with head -1 for the root. Output JSON only.

The accepted failures are often more important: participial modifiers can escape a report/prediction context; a copular noun description can lose its identity link; idioms can retain an unwanted noun participant; and a complex location can remain a text string. Adding syntactically valid frames does not resolve those meanings.

Recommendation for the paper and next implementation
Use one SRL/dependency-to-logic pipeline as the main compiler baseline. Keep parser post-editing as a separately evaluated option; the evidence here does not justify a per-claim SRL/neural selector. The paper’s methods contribution remains probabilistic binding verification with interchangeable evidence functions and learned relation models. The frontend should be a documented component with measured errors.
  1. Complete nominal source scope and participial modifier attachment before expanding acceptance further.
  2. Preserve structured copular/location complements and bind class descriptions to the same referent, rather than using a whole text value.
  3. Make controllers of embedded events explicit. Enhanced dependencies provide additional subject relations for control/raising and shared arguments; test that information rather than assuming every embedded subject is the matrix subject.
  4. Compare the same reviewed reference structures before making a default-parser decision. Keep unsupported constructions explicit.
Primary references: Universal Dependencies enhanced graphs describe the additional control/raising and coordination links. PropBank guidelines define role labels by predicate frameset. Neither resource guarantees that a particular predicted parse is correct.
LLM sentence rewriting remains a reserved last resort and is not implemented.
